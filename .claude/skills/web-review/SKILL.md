# 웹 점검

**눈으로 보지 말고 재라.** 이 저장소의 웹 문제는 전부 "보기엔 괜찮은데
실제로는 잘려 있는" 것들이었다.

```
preview_start {url: "http://localhost:5180"}
resize_window → 360×560 · 390×664 · 390×844 · 1280×800
javascript_tool 로 getBoundingClientRect 를 찍어서 확인
```

**확인할 것은 "보이는가" 가 아니라 "화면 안에 있고 실제로 눌리는가" 다.**

```js
const r = el.getBoundingClientRect();
r.bottom <= innerHeight                                  // 화면 안에 있는가
document.elementFromPoint(cx, cy)?.closest('[data-x]')   // 실제로 눌리는가
```

## 실제로 났던 것 — 이 순서로 의심한다

### 1. `overflow: hidden` + `max-height`

넘친 부분에 **손이 닿지 않는다.** 잘리고 스크롤도 안 된다.
`overflow: auto` 로 두면 모서리는 그대로 깎이면서 넘칠 때만 스크롤이 생긴다.

### 2. `min-height` 가 `max-height` 를 이긴다

CSS 규칙이다. 판과 내용이 **같은 요소**인 걸 잊고 `min-height: 100%` 를
넣었다가 판이 화면을 넘었다. 한 요소에 둘을 같이 두지 않는다.

### 3. `vh` · `dvh` 를 못 믿는 데가 있다

**인스타·카카오 인앱 브라우저**는 위아래 막대를 뺀 높이를 CSS 에 안 준다.
`visualViewport.height` 를 재서 변수에 넣는다.

**그리고 셋 중 작은 쪽을 쓴다.** 자바스크립트가 회전·크기 변화를 한 박자
놓치면 변수가 실제보다 커지는데, 그때 그 값을 믿으면 또 넘친다.

```css
max-height: min(88dvh, 88vh, var(--vvh, 100vh) * 0.88);
```

### 4. 미디어쿼리 순서

같은 명시도면 **나중 규칙이 이긴다.** 모바일 블록이 위에 있으면
아래 데스크톱 규칙에 덮인다 — 모바일 블록을 파일 끝에 둔다.

### 5. 퍼센트 그라데이션

판 높이가 기기마다 다른데 그늘을 퍼센트로 두면 **어떤 폰은 글자가 옅은 데
앉고 어떤 폰은 사진이 다 덮인다.** 픽셀로 고정하고, 글이 시작되는
`padding-top` 과 짝을 맞춰 둔다. **하나를 고치면 하나도 같이 고친다.**

### 6. 넘침

- 그리드 칸은 `minmax(0, 1fr)` — 기본 `min-width: auto` 라 내용이 칸을 넘긴다
- 플렉스 글자는 `min-width: 0` **과** `flex: 1` 둘 다 있어야 한다
- 긴 한글·URL 은 `overflow-wrap: anywhere`

### 7. 화면이 낮은 기기

**세로 여유가 없으면 뭘 줄일지 미리 정해 둔다.** 사진 띠가 45px 커진 것
때문에 '오늘 하루 안 보기' 가 화면 밖으로 밀린 적이 있다 —
사진이 좁아지는 것과 버튼이 안 보이는 것 중에는 앞이 낫다.

### 8. `requestAnimationFrame`

**백그라운드 탭에서는 안 돈다.** 카운트다운·타이머를 여기에 걸면 멈춘다.

## 사이트 특유의 것

- **멤버를 고치면 네 곳을 같이 고친다** —
  `assets/js/members.js` → `index.html` JSON-LD → `<noscript>` → `llms.txt`
- 내비게이션은 한국어 모드에서도 영문 (의도된 것)
- 멤버 사진 크기는 `styles.css` 의 `.member__cut { height }` 한 곳

## 마지막

**푸시하면 1~2분 뒤 바로 공개된다.** 확인 전에 푸시하지 않는다.
